# 457 Map — Change Request Form

**How to use this.** Fill in one block per change you want. Skip any field you do not have an answer for — a blank field is a signal that a decision is still open, which is useful information. Do not try to write a solution; describe what you want and what would make it right. Paste the filled blocks into chat and I will turn them into backlog entries, group them, order them, and write the Codex specs.

**Only three fields really matter:** *What*, *Why / when it bites*, and *Done when*. Everything else is optional context that improves the odds of a correct first implementation.

**Field notes**

- **What** — one or two sentences, plain language. What should be different afterward.
- **Why / when it bites** — the situation where you noticed the need. This is the highest-value field: it tells me the real constraint, which often changes the design. "Hard to find the property after using locate while travelling" led to a much better answer than "add a re-center button" would have.
- **Where** — map / home page / data / GPS tooling / not sure.
- **Who it's for** — me / visitors / both. Owner-only tools can be blunt; visitor-facing things need to stay simple and honest.
- **Devices** — phone only / desktop only / both. Say if the behavior should differ.
- **Done when** — how you'd check it. One concrete observation beats a paragraph of description.
- **Can I test it from a desk?** — yes / needs me on the property. This drives how I group work, since field-verified and desk-verified changes belong in separate batches.
- **Urgency** — now / soon / whenever. "Whenever" is a perfectly good answer and most items should be it.
- **Depends on / related to** — anything that has to happen first, or an existing feature this touches.
- **Reversible?** — note if this changes data, public wording, privacy posture, or anything a visitor could misread. These get extra care and an explicit decision from you.
- **Open questions** — anything you want me to decide or push back on. Say "your call" freely.
- **Notes** — sketches, wording you like, examples from other apps, colors, anything.
